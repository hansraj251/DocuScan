# DocuScan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a production-quality, offline-first Android document scanner that captures physical documents, detects/corrects geometry, applies document enhancement, creates multi-page PDFs locally, and manages saved scans.

**Architecture:** Kotlin/Compose UI is separated from camera, detection, geometry, image processing, scan-session, PDF, and persistence modules. Source captures and processed pages remain local; Room stores metadata while app-private files store images/PDFs. Document detection is exposed behind an interface so the computer-vision implementation can evolve independently of UI.

**Tech Stack:** Kotlin, Jetpack Compose, CameraX, Room, Android PDF APIs, Kotlin coroutines, Android app-private storage, JUnit/Compose tests, SDK 37 / min SDK 26 / Java 17.

**Spec:** `docs/superpowers/specs/2026-10-02-docu-scan-design.md`

## Global Constraints

- Package name: `com.docu.scan`.
- Offline-first: no account, backend, cloud sync, or server-side processing in V1.
- Documents never leave the device in V1.
- Preserve original captures; processing must be non-destructive.
- Manual capture must remain available when detection fails.
- Avoid holding every full-resolution bitmap of a large scan in memory simultaneously.
- Camera permission denial must provide a recovery path.
- Exported PDF page order and orientation must match the scan session.
- Production code follows TDD: write a failing test before implementation wherever behavior can be unit-tested.
- Keep files focused by package responsibility; do not introduce unnecessary architecture or dependencies.

## Review Focus

- Low-light/uneven-light document frames: detection and enhancement must not crash or silently corrupt the source capture.
- Moving phone during auto-capture: auto-capture must debounce/stabilize rather than fire repeatedly.
- Failed/ambiguous detection: manual capture remains usable and editing can proceed without detected corners.
- Large multi-page sessions: page processing/export must avoid retaining all full-resolution bitmaps simultaneously.
- Orientation/rotation changes: preview, edited page, persisted page, and PDF output must retain correct orientation.
